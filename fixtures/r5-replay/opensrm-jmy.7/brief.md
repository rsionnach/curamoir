# opensrm-jmy.7: Override adapter sidecar — HTTP service, batch endpoint, source adapters

Follow-up to opensrm-jmy.4 (which landed the OverrideEvent / privacy / verdict-binding foundation in nthlayer-common). Build the standalone nthlayer-override-adapter sidecar process: POST /api/v1/overrides + POST /api/v1/overrides/batch (last-in-array-wins), OTel emission of gen_ai.override events to the configured collector, generic webhook relay configurable via override-adapter-config.yaml (Jira via dotted-path field mapper already in nthlayer-common), Slack adapter plugin (emoji reactions / slash commands), and an unmatched-override buffer for retry. Covers spec § 4 test scenarios 2, 3, 4, 9 (sidecar webhook, batch import, batch dup-decision_id, Slack adapter). nthlayer-measure consumes overrides via OTel — the adapter's job is translation, not direct verdict-store writes (use apply_override_to_verdict from nthlayer-common only on the OTel consumer path, not inside the adapter).
